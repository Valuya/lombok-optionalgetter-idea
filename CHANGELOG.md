# Changelog

## [Unreleased]

## [1.0.8]

### Fixed

- Every Lombok member, not only `getXxxOptional()`, is resolved again in IntelliJ 2026.2. Its bundled Lombok
  plugin recognises a project as a Lombok project by the Maven coordinate `org.projectlombok:lombok`; the
  overlay's `io.github.valuya:lombok-optionalgetter-overlay` does not match, so that plugin turned itself off
  and `@Getter`, `@Builder` and the rest went red (*"must implement abstract method 'getId()'"*). On project
  open, this plugin now turns on the bundled plugin's own fallback detection, the registry key
  `lombok.slow.jar.detection.enabled`, which finds any library holding the `lombok` package. The bundled
  plugin still generates every built-in Lombok member itself; this plugin adds only `getXxxOptional()`.

## [1.0.7]

### Fixed

- An `@OptionalGetter` field is no longer reported as *"Private field is assigned but never accessed"*: an
  `ImplicitUsageProvider` now marks the field as read by its generated `getXxxOptional()` accessor, matching
  how the bundled Lombok plugin treats `@Getter` fields. Find Usages already found the accessor's call sites;
  this brings the unused-field inspection in line with that.

## [1.0.6]

### Changed

- Point the description and listing graphics at the overlay's new coordinates,
  `io.github.valuya:lombok-optionalgetter-overlay` (renamed from `io.github.valuya:lombok` at the request of
  the Project Lombok maintainers). No functional change: the plugin keys on the `lombok.OptionalGetter`
  annotation, whose fully qualified name did not change, so it works with either artifact.



## [1.0.5]

### Changed

- Renamed the plugin to **OptionalGetter for Lombok** (JetBrains Marketplace does not allow `@` in a plugin
  name). Functionality is unchanged.

## [1.0.4]

### Changed

- Quiet the find-usages diagnostics to debug level (no default log noise); the fix from 1.0.3 is unchanged.

## [1.0.3]

### Fixed

- Find Usages on an `@OptionalGetter` field now reliably includes the generated getter's call sites: the
  handler delegates to the real Java field search and only *appends* the generated getter, and no longer
  depends on the getter being resolvable at handler-selection time (which could make it silently fall back
  to the default handler).

## [1.0.2]

### Fixed

- **Find Usages** on an `@OptionalGetter` field now reliably includes the generated `getXxxOptional()`
  accessor's call sites: the getter is *added* to the field's accessors rather than replacing them, so the
  field's direct references and its `@Setter` accessor are still found too.

### Added

- Marketplace release notes / "What's new" are now published for every version (from this changelog).

## [1.0.1]

### Added

- **Find Usages** on an `@OptionalGetter` field now also finds the generated `getXxxOptional()` accessor's
  call sites, not just direct field references.

## [1.0.0]

### Added

- Initial release: **code completion**, **find usages**, and **go-to-declaration** (onto the field) for the
  `getXxxOptional()` accessors generated by `@OptionalGetter` (from the `io.github.valuya:lombok` overlay).
  The calls no longer show as unresolved in the editor.
